## Core Contribution

RadGraph is an **information extraction (IE) tool** that converts free-text radiology reports into structured knowledge graphs, enabling **clinically meaningful evaluation** of generated reports. It addresses the major limitation of BLEU/ROUGE metrics by capturing medical entities (anatomy, observations, diseases) and their relationships.

**Key Innovation:**
1. **Knowledge Graph Representation:** Converts reports to nodes (entities) + edges (relations)
2. **Clinical Schema:** Defines 14 entity types and 8 relation types specific to radiology
3. **Evaluation Framework:** Enables RadGraph F1 metric for report generation
4. **Public Tool:** Widely adopted standard for evaluating radiology report quality

**Impact:** RadGraph has become the **de facto standard** for clinically grounded evaluation of report generation models (cited 200+ times).

## Methodology

### RadGraph Schema

**Entity Types (14 categories):**

1. **Anatomical Entities:**
   - `ANAT-DP` (Definitely Present): "left lung", "heart"
   - `ANAT-UP` (Uncertain Presence): "possible mediastinal mass"

2. **Observation Entities:**
   - `OBS-DP` (Definitely Present): "opacity", "fracture"
   - `OBS-UP` (Uncertain Presence): "possible pneumothorax"
   - `OBS-DA` (Definitely Absent): "no effusion"
   - `OBS-U` (Uncertain Absence): "no definite consolidation"

3. **Disease Entities:**
   - `DISEASE-DP`, `DISEASE-UP`, `DISEASE-DA`, `DISEASE-U`

4. **Other:**
   - `SEVERITY`: "mild", "severe"
   - `TEMPORAL`: "new", "unchanged", "prior"
   - `MODIFIER`: "bilateral", "diffuse"

**Relation Types (8 categories):**

1. `located_at`: Observation located at anatomical structure
   - Example: "opacity" `located_at` "left lower lobe"

2. `modify`: Modifier describing entity
   - Example: "mild" `modify` "cardiomegaly"

3. `suggestive_of`: Observation suggests disease
   - Example: "infiltrate" `suggestive_of` "pneumonia"

4. `causes`: Entity causes another
   - Example: "pneumonia" `causes` "pleural effusion"

5. `associated_with`: Entities co-occur
   - Example: "edema" `associated_with` "heart failure"

6. `temporal`: Temporal relation
   - Example: "new" `temporal` "opacity"

7. `severity`: Severity modifier
   - Example: "moderate" `severity` "effusion"

8. `uncertainty`: Uncertainty marker
   - Example: "possible" `uncertainty` "mass"

### Example: Report to Knowledge Graph

**Input Report:**
```
"The lungs are clear. There is mild cardiomegaly. 
No pleural effusion or pneumothorax."
```

**RadGraph Output (Knowledge Graph):**

**Entities:**
1. `lungs` (ANAT-DP)
2. `clear` (OBS-DP)
3. `cardiomegaly` (OBS-DP)
4. `mild` (SEVERITY)
5. `pleural effusion` (OBS-DA)
6. `pneumothorax` (OBS-DA)

**Relations:**
1. `clear` → `located_at` → `lungs`
2. `mild` → `modify` → `cardiomegaly`

**Graph Representation:**
```
(lungs) ←[located_at]─ (clear)
(cardiomegaly) ←[modify]─ (mild)
(pleural effusion) [ABSENT]
(pneumothorax) [ABSENT]
```

### Information Extraction Model

**Architecture:** DyGIE++ (Dynamic Graph Information Extraction)

**Input:** Tokenized radiology report

**Pipeline:**
1. **Entity Recognition:** Identify spans corresponding to entities
2. **Entity Classification:** Classify each span into 14 entity types
3. **Relation Extraction:** Identify relations between entity pairs
4. **Relation Classification:** Classify each relation into 8 types

**Training:**
- **Dataset:** MIMIC-CXR subset (14,000 annotated reports)
- **Annotation:** Expert radiologists labeled entities and relations
- **Model:** BERT-based sequence labeling + relation classifier
- **Performance:** 
  - Entity F1: **0.82** (micro-average)
  - Relation F1: **0.76** (micro-average)

## RadGraph F1 Metric

### Evaluation Protocol

**Given:**
- **Hypothesis report** $H$ (generated by model)
- **Reference report** $R$ (ground truth)

**Steps:**

1. **Extract Graphs:**
   - $G_H = \text{RadGraph}(H)$ → Set of (entity, relation) tuples
   - $G_R = \text{RadGraph}(R)$ → Set of (entity, relation) tuples

2. **Graph Matching:**
   - Match entities: exact string match or semantic similarity (BERT embeddings)
   - Match relations: exact edge match

3. **Compute Metrics:**

$$
\text{Precision} = \frac{|G_H \cap G_R|}{|G_H|}
$$

$$
\text{Recall} = \frac{|G_H \cap G_R|}{|G_R|}
$$

$$
\text{RadGraph F1} = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}
$$

**Variants:**
- **Simple Matching:** Exact string match (strict)
- **Partial Matching:** BERT similarity > 0.8 (lenient)
- **Reward:** Weight clinical importance (e.g., missing "pneumothorax" penalized more)

### Typical RadGraph F1 Scores

| Model Type | RadGraph F1 | Interpretation |
|------------|-------------|----------------|
| Random baseline | 0.05-0.10 | Nearly no clinical overlap |
| Template-based | 0.40-0.50 | Captures common patterns |
| R2Gen | 0.35-0.45 | Moderate clinical accuracy |
| State-of-the-art (2024) | 0.50-0.60 | Good clinical content |
| Copy ground truth | 1.00 | Perfect match |

**Important:** RadGraph F1 of **0.45-0.50** is considered clinically acceptable for many applications.

## Advantages Over BLEU/ROUGE

| Aspect | BLEU/ROUGE | RadGraph F1 |
|--------|------------|-------------|
| **Captures Clinical Content** | ❌ N-gram overlap only | ✅ Entities + relations |
| **Paraphrase Robust** | ❌ Penalizes paraphrasing | ✅ Semantic matching |
| **Critical Finding Detection** | ❌ Doesn't differentiate | ✅ Highlights key findings |
| **Absence Modeling** | ❌ Poor at negation | ✅ Explicit absence entities |
| **Correlation with Experts** | Poor (r=0.3) | Strong (r=0.7) |

**Example Demonstrating Superiority:**

**Reference:** "No evidence of pneumonia. Lungs are clear."  
**Hypothesis 1:** "The lungs appear clear without pneumonia."  
- BLEU-4: **0.12** (low due to different words)
- RadGraph F1: **0.85** (same clinical meaning)

**Hypothesis 2:** "There is pneumonia in both lungs."  
- BLEU-4: **0.15** (some word overlap)
- RadGraph F1: **0.00** (opposite clinical meaning)

**Takeaway:** RadGraph F1 correctly identifies Hypothesis 1 as better despite lower BLEU.

## Strengths

1. **Clinical Grounding:** Captures what matters clinically, not just linguistic similarity
2. **Standard Evaluation:** Widely adopted by research community (MICCAI, CVPR, TMI)
3. **Interpretability:** Knowledge graphs are human-readable and debuggable
4. **Public Tool:** Free, open-source, well-documented
5. **Handles Negation:** Explicit modeling of absent findings
6. **Paraphrase Robust:** Semantic matching reduces sensitivity to exact wording
7. **Radiology-Specific:** Schema designed by radiologists for radiology
8. **Quantitative & Qualitative:** Supports both automated metrics and manual error analysis

---

## Limitations

1. **IE Errors Propagate:** RadGraph F1 upper-bounded by IE model accuracy (~0.82 entity F1)
   - If RadGraph misses an entity, evaluation is incorrect
2. **Schema Limitations:** 14 entity types may not cover all radiology concepts
3. **Complex Relations Missed:** Some clinical reasoning not captured (e.g., differential diagnosis logic)
4. **Semantic Matching Ambiguity:** BERT similarity may over-match unrelated entities
5. **No Severity Weighting (Default):** Missing "pneumothorax" penalized same as missing "mild opacity"
   - Can be addressed with custom reward functions
6. **Impression vs Findings:** Works better on findings section; impressions have different structure
7. **Computational Cost:** Running BERT-based IE model adds overhead (~1 sec per report on GPU)
8. **English Only:** Doesn't support non-English reports

## Relevance to Our Project

### Why RadGraph is Essential:

1. **Mandatory Evaluation:** **All report generation papers must use RadGraph F1** (standard requirement)
2. **Replaces BLEU/ROUGE:** Don't report BLEU as primary metric (legacy only)
3. **Factuality Measurement:** Directly measures hallucination (entities in hypothesis but not reference)
4. **Extension Opportunities:**
   - **Training Objective:** Use RadGraph-based loss during training (not just evaluation)
   - **Grounding:** Link generated entities to image regions
   - **Error Analysis:** RadGraph output shows exactly what's wrong

## Implementation Considerations

### Using RadGraph (Evaluation Only)

**Installation:**
```bash
pip install radgraph
```

**Usage:**
```python
from radgraph import RadGraph

# Initialize
rg = RadGraph()

# Extract graph
report = "Clear lungs. Mild cardiomegaly."
graph = rg(report)

# graph = {
#   "entities": {"0": {"text": "lungs", "label": "ANAT-DP"}, ...},
#   "relations": [{"subject": "1", "relation": "located_at", "object": "0"}]
# }
```

**Computing F1:**
```python
from radgraph.metrics import compute_radgraph_f1

f1 = compute_radgraph_f1(hypothesis_report, reference_report)
```

### Compute Requirements
- **Inference:** 1× GPU (can run on CPU, slower)
- **Speed:** ~1-2 seconds per report on GPU
- **Memory:** 2-4 GB GPU RAM

## Comparison with Other Clinical Metrics

| Metric | What It Measures | Pros | Cons |
|--------|------------------|------|------|
| **RadGraph F1** | Entity + relation graph match | Clinically meaningful, standard | IE errors, compute cost |
| **CheXbert** | 14-label classification accuracy | Simple, interpretable | Limited to 14 labels, binary |
| **CheXpert Labeler** | 14-label extraction (rule-based) | Fast, no training | Noisy, rule-based |
| **RadCliQ** | Composite clinical quality | Comprehensive | Complex, not widely adopted |
| **Clinical Efficacy (CE)** | Downstream task accuracy | Practical | Task-specific, needs extra model |

**Recommendation:** Use **RadGraph F1** as primary metric + **CheXbert** for label-level accuracy.
